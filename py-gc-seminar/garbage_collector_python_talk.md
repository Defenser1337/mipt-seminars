## Где ещё возникают циклические ссылки

Цикл возникает, когда по цепочке сильных ссылок можно вернуться к исходному объекту. Для этого не обязательно вкладывать список в самого себя: цикл может проходить через атрибуты объектов, контейнеры и функции.

### 1. Родитель и ребёнок: деревья и графы

Родитель хранит детей, а каждый ребёнок — ссылку на родителя. Так часто устроены деревья объектов, элементы интерфейса и узлы графа.

```python
class Node:
    def __init__(self):
        self.children = []
        self.parent = None


parent = Node()
child = Node()
parent.children.append(child)
child.parent = parent

# parent → children → child → parent
del parent, child
```

После `del` имена исчезли, но объекты по-прежнему ссылаются друг на друга. Одного подсчёта ссылок недостаточно: для освобождения такого недостижимого цикла нужен циклический сборщик мусора.

### 2. Объект хранит собственный метод как callback

Связанный метод (`obj.method`) хранит сильную ссылку на экземпляр в `__self__`. Если экземпляр сохраняет такой метод у себя, получается цикл.

```python
class Button:
    def __init__(self):
        self.on_click = self.handle_click

    def handle_click(self):
        print("Click!")


button = Button()
# button → on_click (связанный метод) → button
del button
```

Похожая ситуация возникает, когда объект хранит диспетчер событий, а диспетчер хранит метод этого объекта среди подписчиков: `объект → диспетчер → метод → объект`.

### 3. Замыкание захватывает объект, который хранит это замыкание

Вложенная функция может удерживать `self` через ячейку замыкания. Если сохранить её в атрибуте этого же объекта, цепочка замкнётся.

```python
class Task:
    def __init__(self):
        self.done = False

        def finish():
            self.done = True

        self.callback = finish


task = Task()
# task → callback → замыкание → self (тот же task)
del task
```

**Что сказать вслух:** циклы — обычное следствие двусторонних связей и обратных вызовов. Пока объект доступен программе, цикл сам по себе не является мусором. Сборщик нужен, когда вся группа объектов стала недостижимой извне, но внутренние ссылки не дают их счётчикам обнулиться.

## Примеры утечек памяти

В Python часто встречается логическая утечка: объект программе уже не нужен, но на него осталась сильная ссылка. Для GC такой объект всё ещё живой, поэтому даже `gc.collect()` его не удалит. Циклические ссылки для такой утечки не обязательны.

### 1. Неограниченный кэш

```python
cache = {}

def get_data(key):
    if key not in cache:
        cache[key] = bytearray(100_000)
    return cache[key]

for key in range(100):
    get_data(key)

# Результаты больше не используются, но cache удерживает их все.
```

Если постоянно приходят новые ключи, память растёт. Решение — ограничить размер кэша, например через `functools.lru_cache(maxsize=128)`, либо удалять устаревшие записи. Сам по себе кэш не ошибка: утечкой он становится, когда хранит ненужные данные без ограничения.

### 2. Забыли отписать обработчик событий

```python
handlers = []

class Window:
    def __init__(self):
        self.data = bytearray(100_000)
        handlers.append(self.on_event)

    def on_event(self):
        pass

window = Window()
del window

# handlers → связанный метод → экземпляр Window → data
```

Удаление имени `window` не удаляет экземпляр: глобальный список хранит его метод, а метод — сам экземпляр. При закрытии окна нужно отписывать обработчик, например `handlers.remove(self.on_event)` в методе `close()`. Для слабых подписок на методы можно использовать `weakref.WeakMethod`, проверяя, жив ли объект перед вызовом.

### 3. Замыкание удерживает большой объект

```python
callbacks = []

def prepare():
    data = bytearray(1_000_000)

    def callback():
        return len(data)

    callbacks.append(callback)

prepare()
# prepare завершилась, но callbacks → функция → замыкание → data.
```

Если `prepare()` вызывается многократно, а обработчики не удаляются, буферы накапливаются. Здесь функции нужна только длина: можно заранее вычислить `size = len(data)` и захватить `size` вместо самого буфера. Ненужные обработчики также следует удалять.

### 4. Сохраняем все завершённые фоновые задачи

```python
import asyncio

tasks = set()

async def work():
    return bytearray(100_000)

async def launch():
    task = asyncio.create_task(work())
    tasks.add(task)
    # Без удаления tasks удерживает задачу даже после завершения,
    # а задача хранит свой результат.
```

Если результаты не нужно хранить, завершённую задачу можно автоматически убирать из набора:

```python
task.add_done_callback(tasks.discard)
```

Эту строку добавляют после `tasks.add(task)`. Результаты и исключения задач при этом нужно обрабатывать отдельно в соответствии с логикой приложения.

**Что сказать вслух:** GC освобождает недостижимые объекты, но не определяет, какие данные нам больше не нужны. Если ненужный объект удерживают кэш, подписка или коллекция задач, исправлять нужно время жизни этих ссылок.
